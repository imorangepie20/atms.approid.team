문서 ID: F02

상태: 첫 서버·첫 거래처 화면 부분 구현·검증 완료, 전표/증빙·거래 이력은 후속

2026-10-06 직전 범위 확인 질문에 사용자 “확정”(계정 보안 검증 스크립트 지정)으로 [첫 거래처 서버 묶음](02-counterparties-foundation-design.md)의 C1~C7·API5개·구현 파일15개·검증8개를 승인했다. 첫 실행 실패 뒤 사용자 “수정해”(schema.prisma 지정)로 같은 범위를 수리했고 기존 연결 회귀시험1파일을 보완했다. 최종8조건PASS·API502/21파일·Appearance16·E2E156·build/lint 종료0이다. 로컬 기본/기존 브라우저 DB에 추가 SQL을 적용하고 기존19업무 테이블씩의 건수/내용 해시 및 과거 기본 migration9행을 보존했다. 현재 UI/API200·새 경로 미인증401이다. 화면·거래 이력과 상위 전체 완료는 후속이다. 처음의 실패와 수리·최종 근거는 담당 설계에 보존한다.

이 문서의 상세 기능, 데이터와 완료 기준은 전체 요구사항을 개발 단위로 풀어쓴 설계안이다. 위 첫 서버 묶음의 실제 완료 근거와 구분하며, 화면·거래 이력 등 미구현 부분의 검증 기준은 실행 결과가 아니다.

거래처 브라우저 부분 완료(2026-10-06): 구체적인 확인 질문 뒤 사용자 “확정”(schema.prisma 지정)으로 [T1~T7·기존API5개·파일14개](02-counterparties-browser-design.md)을 승인해 구현·검증했다. 영향 ID: F02-01~04·06/F08-09·14·15의 화면 부분. 최종8조건PASS·API502/Appearance16/E2E203·build/lint 종료0·실DB버전4/감사3/세션보존/기본21+기존브라우저20테이블전후동일·임시DB/API정리다. 서버 C1~C7/P 정책과 상위 체크는 유지한다. 이전 문서 준비4PASS·실패/수리 이력·이번 화면8PASS를 구분하며 전표/증빙/거래 이력은 후속이다.

## 목적과 범위

회사의 고객사와 공급사 정보를 관리하고 전표 및 증빙에 연결한다.

- 거래처 등록·조회·수정과 검색
- 회사별 식별 및 거래 이력 연결

## 입력과 결과

| 구분 | 내용 |
| --- | --- |
| 입력 | 소속 회사, 거래처 식별 정보와 연락 정보 |
| 결과 | 거래처 목록·상세와 관련 전표·증빙 참조 |

## 데이터와 처리 규칙

- 거래처는 회사 범위 안에서 식별한다.
- 등록번호 등 식별 정보의 형식·중복 정책을 정하고 검증한다.
- 이미 참조된 거래처의 변경이나 사용 중지는 기존 거래 이력을 보존하는 방식으로 설계한다.

## 미정 사항

- 첫 브라우저 화면 T1~T7·구현 파일14개의 선택·범위 확정
- 사업자 정보 확인 연동 여부

필수 입력과 중복 판정은 첫 서버 C2/C3로 확정했다. 실제 목록·등록·상세·수정·사용 중지 화면의 추천값/대안은 위 브라우저 제안에서 확인한다. 거래 이력·증빙·전표 연결과 실제 사업자 확인 연동은 후속이다.

상세 의사결정은 [미정 사항 목록](../ROADMAP.md)을 함께 갱신한다. 새로운 기능이나 계약이 확정되면 이 문서를 수정하고 [인덱스](../README.md)의 범위·참조 경로도 갱신한다.
