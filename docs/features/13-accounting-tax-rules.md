# 회계기준과 세법 변경 관리 개발 문서

[문서 인덱스](../README.md) · [전체 개요](../PROJECT_DECISIONS.md) · [개발 순서와 미정 사항](../ROADMAP.md)

문서 ID: F13

상태: 설계안 및 첫 규칙 버전 서버 기반 구현·검증 완료

이 문서의 상세 기능, 데이터와 완료 기준은 현재 요구사항을 개발 단위로 풀어쓴 설계안이다. 구현 후 검증 기준은 아직 실행 결과가 아니다. 사용자 확정사항과 기존 적용 기록은 별도로 표시한다.

## 목적과 범위

회계 및 세무 규칙의 적용 버전을 관리하고 개정 전후 계산을 재현한다.

- 회계기준·세목별 규칙 버전과 적용 조건
- 개정 검토·검증·승인과 과거 결과 보존

## 입력과 결과

| 구분 | 내용 |
| --- | --- |
| 입력 | 공식 근거, 공표·시행 및 적용 조건, 기업 정보와 입력 스냅샷 |
| 결과 | 선택한 규칙·코드·매핑·서식 버전, 판단 근거와 계산 차이 |

## 데이터와 처리 규칙

- 단순 설정, 복잡한 계산 코드, 계정 매핑과 서식을 별도 버전으로 관리한다.
- 공포일·시행일·사업연도만으로 규칙을 단순 선택하지 않고 적용 조건을 평가한다.
- 확정 결과를 사용한 입력 자료와 모든 규칙 버전에 연결한다.
- 검토 중 개정안과 확정 규칙을 구분하고 AI 해석만으로 자동 적용하지 않는다.
- 누락·충돌 규칙을 검토 대상으로 표시하고 최신 값으로 대체하지 않는다.

## 기존 결정과 상세 요구사항

아래 내용은 종합 문서에서 옮긴 결정 및 요구사항이다. 기술 버전과 적용·검증 기록의 기준일은 2026년 10월 5일이며, 이번 문서 분리 작업에서 기능이나 외부 서비스 상태를 재검증한 결과는 아니다.

### 회계기준과 세법 변경 대응

기업회계기준 및 세법 변동에 대응하는 구조는 사용자 요구사항이다. 아래 내용은 구현 전 설계안이다. 첫 회계기준은 사용자 위임으로 [P-03의 일반기업회계기준](07-financial-statements.md#사용자-위임으로-확정한-첫-회계-범위), 첫 세무 범위는 [P-04의 세무 정책](06-tax.md#사용자-위임으로-확정한-첫-세무-범위)으로 확정했다. 회사별 적용 기준을 기록하고 회계 규칙과 세무 규칙을 분리한다. 회계 장부의 손익에서 세무 조정을 통해 신고용 금액을 산출하는 과정과 조정 근거를 추적하도록 설계한다.

1. **규칙 버전 관리**: 회계기준 종류, 세목, 국가, 버전, 공식 근거 문서와 조문, 공표 또는 공포일, 시행일, 적용 대상 기간 및 조건, 경과조치와 조기 적용 여부를 기록한다. 날짜 하나나 신고 연도만으로 적용 규칙을 고르지 않고 거래일, 사업연도, 기업 유형과 적용 조건을 함께 평가한다.
2. **변경 유형별 구현**: 세율, 한도와 공제율 같은 단순 값은 검증된 설정 데이터로 관리한다. 인식·측정 방식, 세무 조정, 계산 구조 변경은 버전이 있는 계산 코드로 구현한다. 재무제표 분류와 신고 양식은 계정 매핑 및 서식 버전으로 관리한다. 모든 개정을 설정 값만 바꾸어 처리할 수 있다고 가정하지 않는다.
3. **개정 적용 절차**: 공식 자료 확인, 담당자 영향 검토, 새 버전 작성, 검증, 승인, 적용 순서로 진행한다. 검토 중인 개정안과 확정된 규칙을 구분하고 회사·기간별 적용 범위를 명시한다. 자동 수집 결과나 AI 해석만으로 계산 규칙을 활성화하지 않는다.
4. **선택 근거와 충돌 처리**: 계산에 실제 사용한 규칙 ID 및 버전, 적용 판단 근거를 남긴다. 적용 규칙이 없거나 조건이 모호하게 충돌하면 최신 값으로 대체하지 않고 오류 또는 검토 대상으로 표시한다. 규칙의 우선순위와 예외 조건도 검증한다.
5. **과거 계산 재현**: 입력 데이터 또는 스냅샷, 적용 회계기준, 세무 규칙 집합, 계산 코드, 계정 매핑과 보고서 서식 버전을 결과에 연결한다. 한 보고서에서 여러 규칙이 쓰이면 사용한 버전들을 모두 추적한다. 과거 신고·확정 보고서는 이후 개정으로 자동 덮어쓰지 않고 재작성이나 수정신고 결과를 별도 버전으로 남긴다.
6. **개정 전후 비교와 테스트**: 동일한 입력으로 구버전과 신버전 결과 및 차이를 비교한다. 적용일 전후, 연도 중 변경, 사업연도 경계, 경과조치, 조기 적용, 기업 유형별 예외와 반올림을 검증하는 회귀 테스트를 둔다. 세액 변화뿐 아니라 분개, 재무제표 항목과 출력 양식의 변화도 확인한다.
7. **데이터 전환과 복구**: 새 규칙에 필요한 데이터 항목과 계정 매핑을 점검하고 전환 전 백업 및 복원을 검증한다. 향후 계산에 적용할 버전을 이전 버전으로 되돌리는 경우에도 이미 확정한 계산 결과와 사용한 버전은 보존한다.
8. **변경 이력과 안내**: 개정 내용, 영향받는 회사와 기간, 검토자·승인자, 적용 시각을 기록한다. 관리자에게 적용 예정 개정과 처리할 작업을 표시한다. 공식 자료의 변경 확인 방법과 주기는 운영 단계에서 정하며, 현재 자동 감시 작업은 설정하지 않았다.

개정 검토의 공식 자료는 한국회계기준원의 기준서 및 제정개정자료와 국가법령정보센터의 해당 법률·시행령·시행규칙 및 부칙을 우선 확인한다. 한국회계기준원은 [일반기업회계기준의 시행일 및 경과규정 자료](https://www.kasb.or.kr/front/board/View3003.do?accstdSeq=250&gubun=3003&siteCd=002000000000000)를 제공한다. 세법 원문 확인 경로의 예시는 [국가법령정보센터 법인세법](https://www.law.go.kr/법령/법인세법)이다. 이 링크들은 근거 확인 경로이며, 특정 개정의 적용 범위나 현재 세액 계산의 적법성을 검증한 결과는 아니다.

규칙 버전의 첫 서버 기반만 구현했다. 첫 회계·세무 범위는 위 P-03·P-04 정책을 따르며 해당 거래·기간의 공식 근거와 승인된 버전으로 구현한다. 사용자 위임의 P-04에 따라 세무 공통 규칙은 지정 세무 전문가 검토 후 서비스 운영 관리자가 승인한다. 회사 관리자의 신고자료 최종 확인과 구분하고 실제 담당자·근거·검증이 없는 규칙은 활성화하지 않는다. 회계 규칙의 작성·검토·승인·활성화 기능과 운영 책임, 공식 자료 변경 확인 방법·주기는 후속 결정이며 세무 계산식·특례·서식의 기간별 검증도 구현 단계에서 수행한다.

### F13-01~03 첫 규칙 버전 서버 기반

[확정 설계](13-rule-version-foundation-design.md)에 따라 2026-10-06 사용자가 “확인”으로 규칙/불변 버전, 설정·계산·매핑·서식 아티팩트 버전, 회사별 적용 기간과 company.read 조회 범위를 확정했다. 실제 규칙 값은 넣지 않고 계산 코드는 저장소 식별자와 SHA-256만 기록한다. 작성·검토·승인·활성화 API와 운영 책임은 후속 결정이므로 이번 기반 완료와 구분한다.

Prisma 네 모델·아홉 번째 SQL 마이그레이션과 `GET /api/companies/:companyId/rule-applications`를 구현했다. 회사 권한 재검사, 날짜·cursor·limit strict 입력, 회사별 기간 조회, 불변 버전·아티팩트 무결성과 기존 자료 보존을 포함한 전체 413개 테스트 및 컨테이너·로컬 DB 검증이 통과했다. 상세 근거는 [실제 실행 검증 기록](13-rule-version-foundation-design.md#실제-실행-검증-기록)을 따른다.

## 구현 후 검증 기준

- [ ] 적용일 전후·사업연도 경계·경과조치·조기 적용 사례의 버전을 확인한다.
- [ ] 동일 입력의 구버전·신버전 차이를 승인한 계산·분개·서식 결과와 비교한다.
- [ ] 규칙 누락·충돌을 처리하고 선택 근거·검토·승인 이력을 확인한다.
- [ ] 개정 또는 버전 복구 후에도 과거 확정·신고 결과를 재현한다.

## 미정 사항

- P-03·P-04에 따른 적용 기간별 회계·세무 규칙·계산식·특례·서식의 상세 설계·검증
- 회계 규칙 검토·승인 역할, 실제 세무 규칙 담당자 지정 및 공식 자료 변경 확인 방법·주기

상세 의사결정은 [미정 사항 목록](../ROADMAP.md)을 함께 갱신한다. 새로운 기능이나 계약이 확정되면 이 문서를 수정하고 [인덱스](../README.md)의 범위·참조 경로도 갱신한다.
