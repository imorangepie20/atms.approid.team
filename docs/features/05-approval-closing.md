문서 ID: F05

상태: P-02 권한 확정, F05 승인 요청·승인·반려와 POSTED 확정 서버 부분 완료. 마감·정정·확정 화면과 전체 F05 구현 전

이 문서의 상세 기능, 데이터와 완료 기준은 현재 요구사항을 개발 단위로 풀어쓴 설계안이다. 구현 후 검증 기준은 아직 실행 결과가 아니다. 사용자 확정사항과 기존 적용 기록은 별도로 표시한다.

## 목적과 범위

전표의 승인·확정과 회계 기간 마감을 관리하고 정정 이력을 보존한다.

- 작성·승인·확정·마감 상태 전이
- 역분개 또는 연결된 정정과 감사 이력

## 입력과 결과

| 구분 | 내용 |
| --- | --- |
| 입력 | 전표, 회계 기간, 처리자 권한과 승인·마감·정정 요청 |
| 결과 | 상태 변경 결과, 처리 이력과 정정 전표의 연결 |

## 확정한 본인 승인 정책

**P-02 중 작성자·승인자 분리: 회사별 설정, 기본값은 본인 승인 금지.** 확정일과 사용자 선택 근거는 [사전 결정 확정 기록](../PROJECT_DECISIONS.md#사전-결정-확정-기록)을 따른다.

- 기본 상태에서는 승인 권한이 있더라도 자신이 작성한 전표를 승인할 수 없으며 다른 사용자가 승인한다.
- 회사가 본인 승인을 허용한 경우에만 승인 권한이 있는 작성자의 본인 승인을 허용한다. 설정 자체가 사용자에게 승인 권한을 부여하지 않는다.
- 이 설정은 회사별로 적용한다. 다른 회사의 설정이나 승인 권한을 함께 변경하지 않는다.

본인 승인 설정 변경은 회사 관리자의 관리 권한에 포함한다. 회사 관리자는 회계 담당자·승인자 권한도 기본 포함하지만 본인 승인 정책은 그대로 적용한다. 역할별 상세 내용은 [회사 관리자 기본 권한](01-company-access.md#확정한-회사-관리자-기본-권한)을 참조한다.

후속 사용자 위임으로 본인 승인 설정 변경의 처리자·회사·시각·변경 내용을 기록하고 승인 실행 시점의 현재 설정을 적용하기로 확정했다. 인증·감사 정책은 [인증 기본 정책 AUTH-10](01-company-access.md#사용자-위임으로-확정한-인증-기본-정책)을 따른다. 승인 단계는 [첫 묶음 W2](05-journal-approval-foundation-design.md#확정값-w1w8)에서 1단계로 확정하고 서버 요청·승인·반려를 부분 구현했다. 마감 취소·정정 업무 흐름과 확정은 후속 설계다.

승인자 역할의 기본 권한으로 전표 승인·반려·확정을 확정했다. 회사 관리자에게도 이 기본 권한을 적용한다. 본인 승인 정책과 회사 범위·상태별 제한은 그대로 지키며 추가 작업 권한은 아래 후속 확정 기록을 따른다. [확정한 기본 권한표](01-company-access.md#확정한-기본-권한표)를 참조한다.

## 확정한 마감과 정정 권한

확정일: 2026-10-05. 사용자 지시 “이 부분은 일반적으로 사용하는 방식으로 정하고 넘어가자”에 따라 에이전트가 P-02의 남은 역할 권한을 선정했다. 이 표는 프로젝트의 권한 정책이며 회계기준·세법에서 요구하는 역할이라고 주장하지 않는다. 근거와 영향 작업은 [사전 결정 확정 기록](../PROJECT_DECISIONS.md#사전-결정-확정-기록)을 따른다.

| 작업 | 허용 역할 |
| --- | --- |
| 기간 마감 | 회사 관리자, 승인자 |
| 마감 취소 | 회사 관리자만; 사유 기록과 비밀번호 재확인 필요 |
| 확정 전표의 정정 전표 작성·수정·승인 요청 | 회계 담당자, 회사 관리자 |
| 정정 전표 승인·반려·확정 | 승인자, 회사 관리자 |

조회 전용과 외부 세무사 역할 자체에는 이 추가 권한을 부여하지 않는다. 별도 역할을 겸임하면 기존 권한 합산 규칙을 적용한다. 원본 전표 보존, 본인 승인 정책과 회사 범위·업무 상태 제한은 모든 역할에 적용한다. 관리자도 마감된 기간을 곧바로 수정할 수 있는 우회 권한을 갖지 않는다.

F01-05·06, F05-03~07, F08-13에서 이 권한표를 사용한다. 첫 승인 단계는 [W1~W8](05-journal-approval-foundation-design.md)에서 서버 부분 구현했다. 마감 취소 후 재마감·정정 가능 기간과 POSTED 확정은 후속 설계다.

## 데이터와 처리 규칙

- 상태별 변경 허용 범위와 처리 권한을 정의한다.
- 확정 전표 원본을 보존하고 정정은 별도 전표와 근거로 연결한다.
- 마감된 기간의 변경과 마감 취소 정책은 별도로 정한다.
- 보고서 확정과 전표 마감의 연관 관계를 재무제표 문서와 함께 설계한다.

## 구현 후 검증 기준

- [ ] 허용되지 않은 상태 전이와 권한 없는 승인을 거부한다.
- [ ] 기본 설정에서는 작성자 본인 승인을 거부하고, 회사별 허용 설정과 승인 권한을 모두 충족할 때만 본인 승인을 허용한다.
- [ ] 회사 관리자도 기본 설정에서는 자신이 작성한 전표를 승인할 수 없으며, 본인 승인 설정 변경 권한이 해당 회사 범위에 적용된다.
- [ ] 한 회사의 본인 승인 설정을 변경해도 다른 회사의 승인 결과는 바뀌지 않는다.
- [ ] 확정 전표 정정 시 원본과 정정 근거 및 처리자 이력이 유지된다.
- [ ] 마감 기간의 입력·수정과 예외 처리가 정해진 정책대로 동작한다.
