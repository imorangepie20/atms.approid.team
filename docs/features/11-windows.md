# Windows 애플리케이션 개발 문서

[문서 인덱스](../README.md) · [전체 개요](../PROJECT_DECISIONS.md) · [개발 순서와 미정 사항](../ROADMAP.md)

문서 ID: F11

상태: 설계안 및 구현 전

이 문서의 상세 기능, 데이터와 완료 기준은 현재 요구사항을 개발 단위로 풀어쓴 설계안이다. 구현 후 검증 기준은 아직 실행 결과가 아니다. 사용자 확정사항과 기존 적용 기록은 별도로 표시한다.

## 목적과 범위

웹 완성 후 같은 업무 화면과 API를 Windows 앱에서 사용한다.

- Tauri 2 기반 화면 공유, 설치와 업데이트
- 파일 저장·인쇄·알림 등 필요한 네이티브 기능

## 입력과 결과

| 구분 | 내용 |
| --- | --- |
| 입력 | 공유 React 화면, API 설정, 앱 버전과 플랫폼 요청 |
| 결과 | Windows 설치 앱과 필요한 네이티브 기능 결과 |

## 데이터와 처리 규칙

- 온라인 공통 서버 사용은 가정이며 오프라인 요구는 아직 미정이다.
- 파일·인쇄 등 연결 계층을 업무 계산과 분리한다.
- 구버전 앱의 API 호환성과 로그인·업데이트 정책을 정한다.
- Pretendard를 앱에 포함하고 대상 PC 및 프린터에서 검증한다.

## 기존 결정과 상세 요구사항

아래 내용은 종합 문서에서 옮긴 결정 및 요구사항이다. 기술 버전과 적용·검증 기록의 기준일은 2026년 10월 5일이며, 이번 문서 분리 작업에서 기능이나 외부 서비스 상태를 재검증한 결과는 아니다.

### 웹 완성 후 Windows 앱 확장

Windows 앱은 **Tauri 2를 우선 권장**한다. React 화면과 API 클라이언트를 웹과 공유하고, 파일 저장, 인쇄, 알림 등 플랫폼 기능은 별도의 연결 계층으로 구현하는 구상이다. Tauri의 공식 문서에는 Vite 개발 서버와 빌드 결과를 연결하는 설정이 있다. [Tauri와 Vite 연동](https://v2.tauri.app/start/frontend/vite/)

현재 기본 가정은 **공통 서버를 사용하는 온라인 앱**이다. 사용자 확정사항이 아니며, 오프라인 입력과 수정이 필요하면 로컬 저장소, 동기화 및 충돌 처리 설계를 추가해야 한다.

| 항목 | 권장 방향 |
| --- | --- |
| 화면 | 웹과 React 컴포넌트 및 차트 공유 |
| 업무 처리 | 웹과 Windows가 공통 API 및 데이터베이스 사용 |
| Windows 런타임 | WebView2 설치 또는 포함 방식 검토 |
| 배포 | EXE 또는 MSI 설치 파일 |
| 업데이트 | 업데이트 서명과 배포 절차 구성 |
| 인증 | 플랫폼에 맞는 로그인과 세션 보관 방식 검토 |
| API 호환성 | 구버전 설치 앱을 고려한 호환 및 업데이트 정책 |
| 폰트 | Pretendard 파일을 앱에 포함 |

Tauri는 Windows용 EXE 및 MSI 배포와 WebView2 설치 옵션을 제공하며, 업데이터는 서명 검증을 요구한다. [Windows 설치 문서](https://v2.tauri.app/distribute/windows-installer/), [업데이터 문서](https://v2.tauri.app/plugin/updater/)

특수 프린터 제어나 Node.js 라이브러리에 대한 의존이 중요해지면 Electron도 비교한다. 실제 프린터와 대상 PC에서의 기능 및 성능은 아직 확인하지 않았다. Tauri 프로젝트나 Windows 설치 파일은 아직 만들지 않았다.

## 구현 후 검증 기준

- [ ] 대상 Windows에서 설치·실행·로그인과 주요 업무 흐름을 검증한다.
- [ ] 정해진 파일 저장·출력 및 실제 프린터 동작을 확인한다.
- [ ] 서명된 업데이트·실패 처리와 구버전 API 호환성을 검증한다.
- [ ] 오프라인 범위 확정 후 단절·복구와 필요 시 동기화 충돌을 검증한다.
